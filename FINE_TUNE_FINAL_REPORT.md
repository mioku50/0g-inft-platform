## 🔍 **АНАЛИЗ ПРОБЛЕМ**

### **Основная проблема**
Ошибка при попытке пополнения баланса:
```
[fine] formatError:unhandled {
  msg: 'Ledger already exists, with balance: 0.04399999999999835 A0GI',
  type: 'object',
  keys: []
}
```

### **Причины:**
1. **Неправильное использование SDK методов** - использовался `broker.fineTuning.depositFund` вместо `broker.ledger` методов
2. **Непонимание структуры аккаунтов** - есть два типа аккаунтов:
   - Main Ledger Account (общий для всех операций)
   - Fine-Tune Sub-Account (для конкретного провайдера)
3. **Неправильная логика проверки** - всегда пытались создать новый аккаунт вместо пополнения существующего

---

## ✅ **ВЫПОЛНЕННЫЕ ИСПРАВЛЕНИЯ**

### **1. Исправлена логика работы с Ledger аккаунтом**

**Файл:** `web/app/api/compute/account/route.ts`

**Изменения:**
- Использование правильных SDK методов `broker.ledger.addLedger()` и `broker.ledger.depositFund()`
- Добавлена проверка существования аккаунта перед операцией
- Правильная обработка типов данных (SDK ожидает число в OG, не BigInt в wei)

```typescript
// Проверка ledger аккаунта
const ledgerInfo = await broker.ledger.getLedger()
hasLedgerAccount = true

// Правильное использование методов
if (action === 'create') {
  await broker.ledger.addLedger(amountOG)
} else {
  await broker.ledger.depositFund(amountOG)
}
```

### **2. Создан отдельный API для Fine-Tune sub-account**

**Файл:** `web/app/api/compute/finetune/account/route.ts`

**Функционал:**
- Управление Fine-Tune sub-account для конкретного провайдера
- Проверка баланса главного Ledger перед операциями
- Создание и пополнение sub-account через контракт Serving

### **3. Улучшена обработка ошибок**

- Добавлены понятные сообщения об ошибках
- Правильные HTTP коды ответов
- Диагностическая информация для отладки
