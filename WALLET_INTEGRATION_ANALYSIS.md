## 🚨 **ВЫЯВЛЕННЫЕ ПРОБЛЕМЫ**

### **1. Проблема с кошельком**
❌ **Система использует серверный приватный ключ вместо кошелька пользователя**

**Текущая реализация:**
```typescript
const pk = getPrivateKey() // Серверный ключ из .env
const signer = new Wallet(pk, provider) // Серверный кошелек
```

**Проблемы:**
- Пользователи не подписывают транзакции своими кошельками
- Нарушается принцип децентрализации
- Небезопасно для публичного проекта
- Пользователи не контролируют свои средства

### **2. Ограниченный выбор моделей**
❌ **Только 2 модели из 6+ доступных в документации 0G**

**Текущие модели:**
- `llama-3.3-70b` - Language Generation
- `deepseek-r1-70b` - Reasoning

**Отсутствующие модели из документации:**
- `distilbert-base-uncased` - Text Classification
- `cocktailsgd-opt-1.3b` - Language Generation  
- `deepseek-r1-distill-qwen-1.5b` - Reasoning
- `mobilenet_v2` - Image Classification

## 🎯 **ОТВЕТЫ НА ВОПРОСЫ ПОЛЬЗОВАТЕЛЯ**

### **Q: Почему кошелек не запрашивает подпись транзакции?**

**A:** Система использует серверный приватный ключ из `.env` файла:
```env
OG_COMPUTE_PRIVATE_KEY=0x...
```

**Это неправильно для публичного проекта!** Пользователи должны:
1. Подключать свой кошелек (MetaMask, WalletConnect)
2. Подписывать каждую транзакцию
3. Контролировать свои средства

### **Q: Нужны ли дополнительные модели из документации?**

**A:** ДА! Они расширяют возможности платформы:

1. **DistilBERT** - для классификации текста (отзывы, категории)
2. **MobileNet V2** - для работы с изображениями  
3. **DeepSeek R1 Distill** - легковесная модель для простых задач
4. **CocktailSGD-OPT** - для экспериментов с распределенным обучением

**Разные модели = разные use cases = больше пользователей**

## ⚠️ **КРИТИЧЕСКИЕ ЗАМЕЧАНИЯ**

### **1. Безопасность**
- **Текущая система небезопасна** для публичного проекта
- Серверный ключ имеет доступ ко всем средствам
- Пользователи не контролируют свои транзакции

### **2. Соответствие Web3 принципам**
- **Нарушается децентрализация** - все операции через сервер
- **Отсутствует прозрачность** - пользователи не видят транзакции
- **Нет self-custody** - средства контролирует сервер

### **3. Пользовательский опыт**
- Пользователи ожидают подписи транзакций в Web3 приложениях
- Отсутствие выбора моделей ограничивает use cases
- Нет понимания что происходит "под капотом"
